# E0 frontier_random050 figure plan and caption draft

Date: 2026-06-09

This document specifies the manuscript figures for the current Paper10 E0
`frontier_random050` evidence package. It is a figure contract and caption
draft, not a new experiment. Existing plotted drafts are generated by:

```bash
python scripts/paper10/plot_frontier_random050_figures.py
```

The script writes PNG/SVG files under ignored `reviewer_outputs/` by default.

## Figure set argument

The figure set should defend one bounded claim: monitor-gated value filtering
improves GeoJEPA-MPC rollout stability at the reproducible 20x16/top5 scale,
while the tested 50-state label sets expose a candidate-proposal boundary
rather than a successful scale-up.

## Figure 1. Monitor-gated GeoJEPA-MPC value filtering workflow

### Core conclusion

Value-head training is conditional on label quality: candidate labels are first
generated, diagnosed by monitor gates, and only then used for value filtering.

### Archetype

Schematic-led composite.

### Panel map

| panel | content | job |
|---|---|---|

| 1d | Monitor gate checks candidate regret, candidate overlap, and one-step regret | Show why failed label sets are not trained. |
| 1e | Passing label set trains a value head used by `selector=value_filter` in 100-step rollouts | Connect the gate to the rollout evaluation. |

### Caption draft

**Figure 1 | Monitor-gated value filtering for GeoJEPA-MPC.** The workflow
starts from executable candidate actions in the Bishan farmland environment.
A rank checkpoint scores valid actions, and `frontier_random050` combines a
frontier subset with randomly sampled candidates. For each sampled state, the
pipeline records candidate actions, multi-step returns, one-step rewards, and
candidate scores. A monitor gate then tests whether candidate-score top-k
selection has low regret and sufficient overlap with return-ranked top-k
actions while retaining one-step regret. Only label sets with
`decision=continue` are used to train the value head. The trained value head is
then evaluated in 100-step GeoJEPA-MPC rollouts with executable masks,
`selector=value_filter`, horizon 5, global top-k 50, and blend weight 0.1.

### Review risks

- The schematic must not imply that failed 50-state labels were trained.
- The monitor thresholds should appear in either the figure footnote or the
  Methods text.
- The GPKG data-root convention belongs in the Methods or a small callout, not
  as a visual afterthought.

### Caption draft

**Figure 2 | Increasing monitor-gated label coverage improved rollout
stability.** Seed-wise 100-step rollout rewards compare the 10x12/top4 pilot
with the 20x16/top5 scale-up under the same evaluation setting: executable
masks, `selector=value_filter`, horizon 5, global top-k 50, blend candidate
score mode, candidate value weight 0.1, and seeds 0-4. The 20x16/top5 value
filter increased mean total reward from `65.2566` to `69.4705` and reduced the
sample standard deviation from `5.0037` to `1.0004`. The minimum seed reward
increased from `57.9750` to `67.7135`, indicating that the gain was driven by a
tighter rollout distribution rather than a single best seed.

### Review risks

- Do not call this a large-scale result; the validated scale is 20 labelled
  states and 16 candidate actions.
- If an inset uses summary statistics, define sample standard deviation and
  state that the rollouts use seeds 0-4.
- Keep seed0 visible even though 20x16/top5 is lower than 10x12/top4 on that
  seed; hiding it would weaken the credibility of the comparison.

## Figure 3. Failed 50-state labels define the current boundary

### Core conclusion

Larger top-k checks did not rescue failed 50-state rows: some rows became too
close to one-step reward, while others retained high candidate regret or weak
overlap.

### Archetype

Quantitative grid with three aligned diagnostic panels.

### Panel map

| panel | content | job |
|---|---|---|
| 3a | Candidate regret versus monitor top-k | Show regret threshold failures. |
| 3b | Candidate overlap versus monitor top-k | Show candidate coverage failures. |
| 3c | One-step regret versus monitor top-k | Show when labels add little beyond one-step reward. |

The current draft plot is `topk_diagnostic_lines.png/svg` after running
`scripts/paper10/plot_frontier_random050_figures.py`.

### Source data

- `paper10_geojepa_mpc/experiments/results/e0_windows_frontier_random050_ablation_findings_2026-06-09.md`
- `paper10_geojepa_mpc/experiments/results/e0_macos_gpkg_reproduction_findings_2026-06-09.md`

### Caption draft

**Figure 3 | Post-hoc monitor checks show why the tested 50-state labels were
not trained.** Windows seed46 50-state label sets were rechecked at top-6,
top-8, top-10, and top-12 after failing the default top-3/top-4/top-5 monitor
gates. Dashed lines mark the default acceptance thresholds for candidate
regret, candidate overlap, and one-step regret. For `50x16 f0.5` and
`50x20 f0.5`, larger top-k values reduced candidate regret but also reduced
one-step regret, indicating that the labels became mostly explainable by
immediate reward. For `50x24 f0.75` and `50x24 f1.0`, candidate regret and
overlap remained limiting until the top-k became broad enough to weaken the
filtering task. These diagnostics support treating the 50-state rows as a
candidate-proposal boundary rather than training inputs.

### Review risks

- State clearly that these top-k checks are post-hoc diagnostics and did not
  change the training decision.
- If threshold lines are shown, specify the direction of each threshold:
  candidate regret lower is better, candidate overlap higher is better, and
  one-step regret should remain above the minimum.
- Avoid claiming that 50-state scale-up failed in general; only the tested
  candidate proposal / seed / frontier-fraction settings failed.
